# Node — nonlinear equation workbench

A browser-based nonlinear algebraic equation solver built with TypeScript, React, Vite, and Plotly. Equations are the source of truth: there are no required transistor parameters, circuit objects, schematic, server, or Python runtime. All numerical work runs in a cancellable Web Worker. New workspaces start with `y = a*x + b;`; circuit examples remain optional.

## Run

Install [Node.js](https://nodejs.org/) (the current LTS release, version 22 or later) and [Git](https://git-scm.com/), then open a terminal in this project:

```sh
npm ci
npm run dev
```

Open the URL printed by Vite. `npm test` runs numerical tests; `npm run build` type-checks and creates a self-contained `dist/index.html`; `npm run preview` serves that build.

To run the built app without Node.js or a local server, open `dist/index.html` directly in Chrome or Edge. You can share that single file: it includes the app, styles, and solver worker. The same file can be deployed to any static host. Fonts use local system fallbacks and no remote assets are required. No equation or parameter data is transmitted.

VS Code's **Terminal → Run Task** menu has **Run workbench**, **Build workbench**, and **Test workbench**; **Ctrl+Shift+B** builds. These tasks use your installed Node.js and npm. After installing Node.js or Git, restart VS Code so its terminals and tasks receive the updated PATH. In Windows PowerShell, use `npm.cmd` in place of `npm` if an execution policy blocks `npm.ps1`; the VS Code tasks already do this.

Keep `package-lock.json` in Git so `npm ci` installs the same dependency versions on another machine. Dependencies, build output, and local runtime downloads are ignored by Git.

## Use

1. Open the settings gear in the graph header to load the NMOS, CMOS inverter, or multi-root cubic example. The workspace uses the full viewport, with equations on the left, the graph on the right, and parameter sliders below.
2. End every equation with `;`. Equations may span multiple lines, and multiple equations may share a line. Equalities become left-minus-right residuals; a plain expression is interpreted as a zero residual. `#` starts a comment through the end of the physical line. Older configurations containing no semicolons still accept newline-separated equations.
3. Every editor tab accepts unknowns, parameters, equations, and validity checks in any mixture. All tabs share one namespace and solve together. Use **+** to add a tab, the pencil or a double-click to rename it, and the trash button to remove it. The top controls are ordered add, rename, delete. New tabs organize the same model; switching or renaming them starts no solve. Enter `unknown name` or `unknown name guess`, one declaration per line or separated with semicolons. For parameters, enter `parameter name value step min max`, omitting trailing options you do not need. Guesses and parameter values default to **0**. The parameter options are always **value / sweep start, step, slider minimum, slider maximum**, in that order. A parameter without the complete step and bounds has a numeric control without a slider. Numeric options accept expressions such as `9e-9`, `9*10^(-9)`, or `(2 * pi)`; wrap expressions containing spaces in parentheses. Comments start with `#`. Incomplete or invalid declarations stay visible and show an error; errors identify their tab and line, and the solver pauses until the source is valid. Bulk paste, Enter, and Backspace use ordinary text editing.
4. Add trailing `sweep` after all four parameter options to select a sweep, for example `parameter VDD 5 1 0 10 sweep`. The current main sweep remains main while marked; otherwise the first marked parameter becomes main. Every other marked parameter supplies a slice dimension with an independent slider. Removing the main parameter's `sweep` keyword promotes the first remaining marked parameter. At least one is required to run a free sweep. The range, step, and starting value determine all sampled values and point/slice counts; **Diagnostics → Sweep plan** shows every selected axis and the combined workload. Parameter sweeps use additive step sizes. Axis expressions are independent of the swept parameter: e.g. sweep `VG`, plot `VD` versus `ID * 1e3`. To plot multiple quantities, separate Y expressions with commas, for example `ID, VD, max(ID, 0)`. Each expression gets its own color and legend entry on the shared Y scale; commas inside function calls are preserved. Clicking a legend entry hides or shows that curve across its branches.
5. Auto-run applies to all sweeps: editing valid declarations, equations, or settings recomputes after a short debounce and terminates superseded workers. Disable Auto-run for manual Run control. There is no automatic history cache. Each combination of slice parameter values contains a full main sweep, and the graph still shows the same X and Y expressions. Each run first selects the combination of configured starting values. Sliders show current numeric values; the graph area identifies all selected values. Edit the first parameter option to change its configured sweep start. Moving any slice slider changes only that parameter's selected coordinate, starts no solve, and never changes the configured starting values. Sliders use sample indices so every position has a corresponding value; no interpolation is performed. Failed combinations retain their own error and display no curve.
6. Drag the thin divider between equations and graph to change their widths; drag the line above Parameters to change the bottom tray's height. Panels sit flush, separated by subtle outlines. The chevron controls collapse the equation sidebar or slider tray; visible rails reopen them at their previous sizes. Panel sizes and collapsed states are remembered locally. Double-click a divider to reset it; focused dividers also accept arrow keys (Shift for larger steps) and Home/End. Open **Settings → Graph scale** to shrink or stretch the horizontal and vertical axes independently, from 25% to 400%. Higher percentages enlarge the curve along that axis; **Fit graph** restores automatic scaling. These view controls update immediately without recomputing the sweep, and their scale preferences are remembered locally. Scroll the graph to zoom, drag to pan, double-click to autoscale. Plotly's toolbar includes reset and SVG export. Click a point for solution values; fixed inputs, residuals, and the Jacobian are in expandable sections. **Diagnostics** groups model counts, sweep planning and limits, grid progress, and result quality. Current inputs and results from previous settings are labeled separately. The layers button preserves one previous curve when axis expressions match.
7. The settings menu contains New equation workspace, workspace naming, Save, JSON import/export, Quick guide, and Diagnostics. Sweep, Solver, and Graph settings have separate sections in the same dialog. Save stores one workspace in browser local storage. Import/export JSON preserves tab names, ordering, comments, and text, including unfinished drafts. Tab sources are authoritative; engine fields are compiled from all tabs. Legacy workspaces receive an Equations tab and a combined Definitions tab on load. Up to 32 tabs and 200,000 source characters are supported, within the existing 100-declaration and 50,000-character math limits. Put validity conditions and derived relationships in any tab. For example, `y >= 0;` filters roots, and `twice = 2*y;` defines a computed quantity without a declaration. Use `valid expression;` for an explicit Boolean validity check, including predicates whose outer syntax resembles arithmetic. Only symbols used by equations, axes, validity conditions, and the sweep participate in a solve. Unused declarations remain editable and can be removed from their tabs. Older configurations move separate derived expressions and validity conditions into Equations, including explicit unknown bounds; parameter slider ranges are retained. Region coloring is deferred; legacy region metadata is ignored and cannot introduce parameter requirements.

For example, the following declarations and equations can share one tab or be split across several:

```text
# Unknowns
unknown y 1

# Parameters: name, value/start, step, min, max, optional sweep
parameter x 0 0.1 -5 5 sweep
parameter gain 2
parameter offset
```

The same tab, or another tab, can contain relationships and validity checks:

```text
y^2 = gain*x + offset;
twice = 2*y;
y >= 0;
```

Here `offset` defaults to zero, `gain` and `offset` have numeric controls, and `twice` is reconstructed from each solution without becoming an independent Newton variable. The unknown count must match the remaining equation count after safe assignment elimination; the solver explains underdetermined or overdetermined systems.

### Expressions and units

Safe recursive-descent parsing; no eval, Function, property access, assignments, or arbitrary JavaScript. Supports `+ - * / ^ **`, parentheses, comparisons, `&& || !`, lazy `if(condition, a, b)`, nested conditionals, and ternary syntax. Use explicit multiplication. Functions: `abs sqrt exp log ln log10 sin cos tan asin acos atan atan2 sinh cosh tanh min max pow floor ceil sign`. Constants: `pi e true false`. Scientific notation and attached engineering suffixes work: `1e-3`, `2.2k`, `500u`; supported suffixes are p/n/u/m/k/K/M/G/T, case-sensitive. Unit labels like `V` and `Ohm` are not parsed. Internal values are SI.

Line breaks are whitespace inside semicolon-terminated equations. Nested `if` calls use their existing parentheses and commas; braces are unnecessary:

```text
(VDD - VD) / RD = ID;
ID = if(
  VG <= VTH,
  0,
  K / 2 * (VG - VTH)^2
    * (1 + LAMBDA * VD)
);
```

The supplied NMOS example uses current positive into the drain, ground-referenced voltages, and positive threshold magnitude. The PMOS example uses positive source-to-drain current and positive threshold magnitude; output KCL equates NMOS and PMOS currents. Circuit examples provide initial guesses without preset unknown bounds, so changing the equations does not inherit hidden current/voltage restrictions. Add any intended bounds as validity conditions in Equations. Older saved configurations have their explicit unknown bounds moved into those conditions. A sweep with no plotted points raises an error; bound-limited failures identify the variable and limit. Arbitrary equations determine your sign conventions. Capacitors contribute no current in ideal DC; AC, transient, noise, schematic capture, and SPICE netlists are outside this version's scope.

### Free and constrained sweeps

A free sweep varies a fixed parameter while solving the same unknowns. Choosing a dependent quantity for the X axis does not impose it. In **Sweep settings**, constrained mode instead fixes a chosen unknown at each sweep value and releases a fixed parameter as an unknown, preserving the square equation system. Bounds on the released parameter become unknown bounds. Choose sweep limits consistent with your physical model; the swept coordinate is explicitly imposed by the sweep.

A sweep grid adds fixed parameters distinct from the main, any released parameter, and each other. For example, with `y = a*x + b;`, add trailing `sweep` to complete declarations for `x`, `a`, and `b`. If `a` and `b` each have three samples, the app computes nine curves, and their sliders choose which `(a, b)` combination is displayed while X remains `x`. More swept parameters add further slider dimensions. Their counts multiply: three extra parameters with three samples each require 27 full main sweeps. Editing equations, variables, constraints, axes, or sweep/solver settings invalidates the dataset and recomputes it when Auto-run is checked; otherwise select Run. Moving slice sliders preserves the computed set and configured starting values. You can browse completed combinations while later ones are being computed; an unfinished combination is visibly empty until its preview or result arrives. Stop cancels the remaining work and keeps completed combinations available. Only the current dataset is retained. Save/export stores all dimension settings; computed slices are session-only and are recomputed after reload when Auto-run is checked. Older single-extra workspaces remain compatible.

Parameter sweeps begin at their configured starting values and expand outward, lower before higher at equal distances. With one extra parameter, `VDD` start 5, min 0, max 10, and step 1 computes `5, 4, 6, 3, 7, 2, 8, 1, 9, 0, 10`. With several extras, the starting combination comes first, followed by combinations with the fewest total sample steps from it. Combinations are generated lazily rather than allocating the full product beforehand. Main-sweep points use the same centered order but plot in increasing parameter order. Each direction has its own adjacent-point continuation seeds, so alternating work does not create zigzag lines or bridge failed samples. Changing the starting value can change finite multistart root discovery; exhaustive discovery is still not guaranteed. An off-grid start anchors its own grid: start 5.2 with step 1 samples 5.2, 4.2, 6.2, etc., staying inside the range. Bounds are included when a step lands on them. The starting value must be inside the range, and step must be positive and produce distinct finite values. A step wider than the range gives one sample.

Main sweeps support up to 50,000 derived points, each additional parameter supports up to 10,000 samples, and the full grid supports at most 250,000 positions: main points multiplied by every additional parameter's count. These larger limits target desktop browser use; smaller steps and more dimensions can increase computation and graph rendering time substantially. Oversized sweeps report the requested count, limit, and contributing axis counts; a suggested step or per-axis sample target helps reduce the request. Counting does not allocate sample arrays, and large products use exact integer arithmetic when the individual counts are representable. Oversized products are rejected before combination allocation; steps are never silently enlarged. Every dimension shares the same conservative 1,000 MiB retained-data budget, checked after each sample and including point values, residuals, sampling plans, combination bookkeeping, and container overhead. Dense Jacobians are computed when a point is inspected, rather than retained for every sample. If the dataset exceeds that limit, computation stops and the incomplete dataset is released; increase step sizes, narrow ranges, or reduce multistart guesses before retrying. Multiple roots and larger value dictionaries can exhaust the budget before reaching the point limit. The budget covers estimated retained sweep data; solver scratch space, worker transfers, overlays, and Plotly allocations use additional memory. Individual combinations without solutions do not prevent the remaining combinations from being computed. Older saved workspaces with missing selected-parameter range/step fields receive visible defaults from their legacy sweep settings; explicitly set Parameters values always take precedence. Constrained sweeps still configure the imposed unknown's range and point count in **Sweep settings**. Solver tolerance, iteration limits, and starting guesses are edited in **Solver settings**.

## Numerical method and limits

The independent engine is in [src/core](./src/core/). A single identifier on the left of an equality can introduce a computed quantity without a separate declaration. Complete acyclic assignment chains such as `Ra = R1 + R2;` keep their direct evaluation path, independent of initial guesses and Newton's absolute tolerance. A fully linear system with coefficients fixed at the current sweep point is also solved directly using scaled Gaussian elimination with pivoting, including coupled cycles. This handles equations such as `2*x = p;` and cyclic linear assignments without Newton iterations. Zero or unsafe pivots, singular systems, unsupported expressions, and inaccurate direct candidates fall back to the numerical path. The original expressions, domains, bounds, and validity conditions are still checked.

Mixed systems use conservative assignment elimination plus simple linear isolation: `y = x - sin(y);` can reconstruct `x = y + sin(y)` while Newton solves the remaining equations in `y`. An isolated variable's coefficient must be fixed and nonzero at that sweep point; a coefficient depending on another numerical unknown is left implicit. The planner keeps whichever supported plan removes more variables, reconstructs eliminated values at every residual/Jacobian evaluation, and retains all values for plotting and inspection. Inclusive search bounds keep affected variables numerical during partial elimination to preserve endpoints despite rounding. This is a bounded greedy reduction, without general symbolic expansion, quadratic formulas, inverse-function branch enumeration, or a search for the largest solvable partial block. Preparation is repeated per sweep point; fixed-only assignment calculations are reused within that point's solve.

The remaining implicit system uses a central finite-difference Jacobian (one-sided at domain boundaries) and pivoted Gaussian elimination for a Newton step. Unknowns use characteristic scales from guesses/bounds and residual rows use fixed scales from the initial residual and Jacobian. A backtracking line search accepts only residual merit decreases. When Newton fails, adaptive Levenberg-style regularized normal equations provide safeguarded steps. Simple inclusive validity limits such as `x >= 0` or `x <= VDD` also guide search when the other side depends only on fixed or swept parameters. All conditions are checked at the root. Strict, compound, and unknown-dependent conditions are checked only after solving, so they may require more guesses or miss roots compared with explicit search bounds. Both scaled and raw residual criteria are checked on the numerical path; failed solves never generate synthetic points. The inspector exposes raw residual infinity norm and computes the Jacobian at the selected point's actual parameter values. Mixed reduced systems report their numerical equations and unknowns; complete direct systems retain their full equation diagnostics. Direct `solve`/`roots` calls still include Jacobians by default; sweep samples store an empty matrix until inspected.

On the numerical path, deterministic Halton multistart guesses cover bounded intervals or a finite neighborhood of the initial guess. Roots are deduplicated in scaled unknown space. Sweeps seed each point with preceding roots and retain multistart discovery. Greedy one-to-one distance matching connects adjacent points, with a conservative maximum normalized distance; failed samples and large jumps split branch segments. Proven single-valued continuous assignment chains instead continue their unique branch across adjacent valid samples, avoiding artificial fragmentation when a frequency is many orders larger than its initial guess. Piecewise conditions and step functions retain the jump heuristic, and undefined samples break every path. Poles between sampled coordinates may require finer resolution. Closely spaced numerical roots can still be misassociated. Branch IDs identify plotted segments, not globally guaranteed mathematical branches. Flat or singular models can yield nonisolated roots. Neither exhaustive root discovery nor dynamic stability is claimed. Increase starts/resolution, improve guesses/scales, or add physically justified bounds/conditions when needed. Pseudo-arclength continuation is not implemented.

Sine is periodic, so different values of an unknown can produce the same output. With both `y` and `z` unknown, `z = sin(y);` alone is underdetermined. Adding `z = 0.5;` leaves infinitely many possible `y` values; finite multistart search can find some, without claiming all of them. The optional interval below restricts the solution to `y = pi/6`. Alternatively, `y = a; z = sin(y);` for a fixed parameter `a` directly determines both outputs.

```text
z = sin(y);
z = 0.5;
# Optional validity interval selects one sine branch:
y >= -pi/2;
y <= pi/2;
```

Piecewise functions evaluate the active branch at every candidate, including numerical derivative samples. Line search and regularization help at kinks but cannot guarantee convergence for discontinuous systems. Invalid expressions, singularities, nonconvergence, constraints, and failed plotted expressions appear in diagnostics. A red status dot indicates an error; click it for the message. A compact amber status indicates a partial sweep; click it to inspect failures. If one Y expression is undefined at a point, its curve has a gap while other valid expressions remain plotted. Unknown bounds reject roots outside their interval, so they can create gaps or shorten the plotted portion of a sweep even when the requested parameter range is larger. Save/export is explicit. A failed computation clears the previous successful result so a stale curve cannot be mistaken for a solution of the edited equations.

Diagnostics labels solved samples separately from plotted roots and calculation issues: one sampled coordinate may have several roots or failed plot expressions. Branch segments count connected curve portions. Grid progress counts finished combinations, including failed slices; its total elapsed time is separate from the displayed curve's solve time. Limits describe the retained sweep-data budget, not measured browser heap usage. Diagnostics memoizes the displayed curve summary and never scans all retained slices.

Long sweeps populate the graph as samples finish, with previews sent at most about every 200 ms between samples. Progress appears in the persistent status beside the axis expressions; the graph's slice row shows only the selected parameter values and position. The progress counter includes both successful and failed samples. Previews transfer only new points and diagnostics; worker messages and plot renders are bounded so a slow graph cannot queue unlimited snapshots. Numerical solving remains in one worker to preserve continuation seeds and branch matching, while the main thread plots results. Live plotting improves feedback and adds some transfer/rendering overhead; it does not accelerate a new numerical solve. Additional sweeps acknowledge each completed slice before starting the next so completed results cannot queue indefinitely.

The supplied [resistor-noise regression workspace](./src/core/fixtures/resistor-noise.json) is an acyclic assignment chain spanning resistances, frequency, and signals around `1e-13`. Its defined domain has `Stot = k*T/C = 4.14e-13`; `S3/S4 = R4/R3`, so `S3` and `S4` overlap exactly when `R3 = R4`. Hide either legend entry to inspect the other. Zero `R3` or `R4`, and simultaneous zero `R1` and `R2`, leave divisions by zero in the original equations. Those coordinates remain diagnostic gaps; positive resistance minima exclude them.

## Tests

[src/core/solver.test.ts](./src/core/solver.test.ts) checks parsing and security rejection, engineering notation, linear/nonlinear known solutions, root deduplication, constraints and bounds, dependency cycles, piecewise boundaries, failed solves, branch gaps, arbitrary plot coordinates, logarithmic/constrained sweeps, transistor sweep coverage, the analytic zero-lambda NMOS result, and JSON imports.

Additional tests cover declaration defaults and positional options, invalid declarations, sweep selection, legacy equation-input migration, partial assignment elimination, inferred definitions, exact assignment dependencies, relative accuracy of tiny signals, singular and piecewise gaps, on-demand point Jacobians, parameter-derived sampling, center-first computation, separate continuation directions, prepended progress updates, analytical slices, memory limits, failed-slice recovery, worker backpressure, cancellation, ordinary sweep recomputation, secondary variable maintenance, and bounded plot scheduling.

The engine and worker are independent of React. Automatic differentiation can replace `jacobian`, advanced continuation can replace branch matching, and future small-signal analysis can consume the returned physical Jacobian without changing equation input.
